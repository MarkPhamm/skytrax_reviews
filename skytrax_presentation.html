Tech stack — and why I chose each

LayerChoiceWhy (trade-off)
Warehouse Snowflake Managed cloud DWH — COPY INTO bulk loads, RBAC, tag-based masking, compute decoupled from storage.
Transform dbt Core Tests, docs, contracts, incremental, defer/state — portable vs Cloud lock-in for this project.
BI Mode Analytics Warehouse-direct, SQL-first — every chart is a defensible query; Delta / Frontier / Spirit Mode slices from analyst partners.
Orchestration Airflow + Datasets + cosmos Event-driven crawl→process→load; cosmos makes dbt graph first-class tasks.
Ingestion Custom Python scraper Skytrax has no public API — Fivetran/Airbyte can’t land HTML reviews; polite crawl + parse into replayable files instead.
Landing AWS S3 Replayable raw archive; decouple scrape from load; cheaper than warehouse history.
IaC Terraform (AWS + Snowflake roots) Every bucket, role, schema, warehouse, mask, CloudFront, OIDC provider — reproducible, reviewable, no click-ops drift.
CI/CD + Auth GitHub Actions + OIDC PR: SQLFluff + slim state:modified+ build; CD: defer/favor-state; GHA assumes AWS IAM via OIDC — no static cloud keys.

Pillar 2 · Aggregates & history

Airline scorecards + SCD2 score drift

agg_airlines_review

  • Grain: one row per airline with ≥1 fact review
  • Rollup from fct_review + dim_airline
  • Volume: review / verified / recommended / layover counts
  • Quality: avg_rating + 7 service averages
  • Bands: good / medium / bad / unknown counts
  • Rates: pct_recommended, pct_verified
  • Contract enforced — scorecard-safe for Mode

Why not query the fact every time?

Pre-aggregated airline grain for ranking & peer compare — Mode and analysts hit a stable scorecard table instead of re-rolling 160K+ fact rows.

snap_agg_airlines_review

  • Schema: SNAPSHOTS · unique key airline_id
  • check strategy on metric columns
  • New SCD2 version when counts / avgs / rates change
  • dbt_loaded_at excluded — no-op rebuild ≠ false change
  • Also: snap_skytrax_reviews (timestamp) audits review edits upstream
{% snapshot snap_agg_airlines_review %} {{ config( schema='SNAPSHOTS', unique_key='airline_id', strategy='check', check_cols=[…metrics…], -- not dbt_loaded_at ) }} select … from {{ ref('agg_airlines_review') }} {% endsnapshot %}

Pillar 2 · Show → Why → What-if

Data Transformation

Show

Where it lives

  • marts/fct_review.sql — incremental merge
  • marts/aggregated/agg_airlines_review.sql
  • snapshots/snap_agg_airlines_review.sql (check)
  • snapshots/snap_skytrax_reviews.sql (timestamp)
  • Live: dbt run -s agg_airlines_review · dbt snapshot
Why

Trade-offs

  • Incremental merge — 160K+ history; don’t rebuild full fact daily.
  • Lookback window — late-arriving updates / clock skew without full refresh.
  • Airline agg — scorecard grain; contract keeps BI columns stable.
  • Check snapshot — track score drift; exclude load timestamps so rebuilds don’t invent versions.
What-if

Live adaptations

  • “New service score column” → contract + extend avg formula + unit test; add col to check_cols; full-refresh fact + snapshot.
  • “How did Delta’s avg move?” → query snap_agg_airlines_review by dbt_valid_from / dbt_valid_to.
  • “Delete / GDPR erase” → dbt run-operation gdpr_erase clears fact + snapshot rows + exclusion seed.

Pillar 5 · DataOps

Terraform · OIDC · CI/CD — how the platform is run

Terraform (IaC)

Nothing important is click-ops.

  • EL repo: S3 landing, IAM, Snowflake RAW tables, stage, LOAD_AUDIT, PII tags/masking
  • Transform repo: warehouses, RBAC, SOURCE/INTERMEDIATE/MARTS/DEV_*, artifact bucket, CloudFront, OIDC provider + IAM role
  • terraform apply stays manual on purpose (infra blast radius)

OIDC auth

GitHub Actions never stores static AWS keys.

  • Terraform creates GitHub OIDC provider + deploy role
  • CD job: aws-actions/configure-aws-credentials → short-lived creds
  • Role can: read/write dbt artifacts S3, invalidate CloudFront
  • Snowflake still uses service users (DBT_CICD / PROD_DBT) via GitHub secrets

CI / CD release

Ship only what changed.

  • CI (PR): merge-base → SQLFluff → clone prod → build/test state:modified+
  • CD (main): download prod manifest → dbt build --defer --favor-state
  • Publish docs → S3 → CloudFront invalidate
  • Email alert: CD always notifies me — failure lands in inbox with run link
  • Airflow/cosmos schedules ongoing prod dbt; GHA ships code

Pillar 5 · Show → Why → What-if

DataOps

Show

Where it lives

  • .github/workflows/pr_checks.yml
  • .github/workflows/deploy_main.yml — email on fail/success
  • Terraform AWS OIDC + S3 artifacts + CloudFront
  • GitHub Actions badges / recent run logs
  • Docs: docs/cicd.md
Why

Trade-offs

  • SQLFluff in CI — style/syntax gate before warehouse compute.
  • Slim CI — full project build on every PR is slow/expensive.
  • Trailing + — rebuild downstream after dbt clone so types don’t silently stale.
  • Defer/favor-state — prod only rebuilds blast radius.
  • CD email — don’t rely on checking Actions; failure hits my inbox with the run link.
What-if

Live adaptations

  • “Block merge if freshness fails” → add dbt source freshness step in PR or nightly.
  • “Blue/green schemas” → deploy to MARTS_NEXT, swap grants after tests.
  • “Multi-dev conflict” → already isolated DEV_*; show clone-from-prod pattern.
